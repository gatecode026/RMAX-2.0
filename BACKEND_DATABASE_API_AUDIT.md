## 1. Database Model & Schema Integrity

Mongoose 9 schemas were audited for index coverage, foreign key references, cascading constraints, and atomic sequence safety.

### 17 Verified Mongoose Models

1. **`User` (`src/models/User.ts`)**:
   - `email`: Indexed, unique, lowercase, trimmed.
   - `role`: Enum `["customer", "manager", "admin", "super_admin"]` with default `"customer"`.
   - `status`: Enum `["active", "inactive", "suspended"]`.
   - `passwordHash`: Configured with `select: false` to prevent accidental credential leakage in queries.

2. **`Lead` (`src/models/Lead.ts`)**:
   - `leadNumber`: Unique indexed string generated by atomic `Counter` (`LEAD-YYYY-XXXX`).
   - `assignedManager`: ObjectId reference to `User`, indexed for manager dashboard queries.
   - `status`: Enum `["new", "assigned", "contacted", "qualified", "converted", "lost"]`.
   - Compound Index: `{ assignedManager: 1, status: 1 }` enables sub-millisecond manager pipeline filtering.

3. **`QuoteRequest` (`src/models/QuoteRequest.ts`)**:
   - `quoteNumber`: Unique indexed sequence string (`QUO-YYYY-XXXX`).
   - Links directly to customer `User` and created `Lead` record.

4. **`Order` (`src/models/Order.ts`)**:
   - `orderNumber`: Unique indexed sequence string (`ORD-YYYY-XXXX`).
   - `items`: Subdocuments with snapshot pricing and specifications at the time of purchase.
   - `paymentStatus`: Enum `["pending", "paid", "failed", "refunded"]`.
   - `fulfillmentStatus`: Enum `["unfulfilled", "processing", "shipped", "delivered", "cancelled"]`.

5. **`Counter` (`src/models/Counter.ts`)**:
   - Used with `findOneAndUpdate({ _id: key }, { $inc: { seq: 1 } }, { new: true, upsert: true })` to guarantee sequential numbers without race conditions.

## 2. API Design & REST Conformance

### HTTP Methods & Status Code Adherence
- `GET`: Read operations with deterministic JSON structures and explicit pagination (`page`, `limit`, `total`, `totalPages`).
- `POST`: Creation endpoints returning `201 Created` with created entity payload, or `400 Bad Request` on validation failure.
- `PATCH`: Partial state updates (e.g. lead status transition, manager assignment).
- `DELETE`: Soft/hard delete with authorization verification.

### Input Validation
All API endpoints ingest payloads through strict Zod schemas:
- Email sanitization and regex validation.
- Phone number length and numeric checks.
- Quantity bounds checks (`Math.max(1, qty)`).
- SQL / NoSQL injection prevention via Mongoose typed schema casting.

## 3. Transactional Consistency & Concurrency

1. **Quote Submission Flow**:
   ```text
   Inbound POST /api/quote-requests
   ├── Validate body with Zod
   ├── Atomic Counter increment for sequence ID
   ├── Insert QuoteRequest document
   ├── Insert Lead document with initial status "new"
   ├── Dispatch real-time Notification event via SSE
   └── Return 201 with quoteNumber and confirmation
   ```
2. **Order Placement Flow**:
   ```text
   Inbound POST /api/orders
   ├── Revalidate product prices against MongoDB (never trust client prices)
   ├── Validate inventory stock availability
   ├── Atomic sequence Counter increment
   ├── Persist Order document
   ├── Atomic inventory stock decrement
   └── Dispatch notification to Admin order queue
   ```

## 4. Query Performance & N+1 Prevention

- **Aggregation Pipelines:** Dashboard KPI calculations (`/api/admin/overview`, `/api/admin/reports`) utilize `$facet`, `$group`, and `$match` pipelines, eliminating in-memory JavaScript loops over large datasets.
- **Population Hygiene:** Populating references (`assignedManager`, `institution`) uses lean queries (`.lean()`) with restricted projections (`.select("name email phone")`), minimizing serialization overhead.
